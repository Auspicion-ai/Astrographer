## 0. Intent (mechanism-independent)

The proposal needs: (i) an operator-authored, server-side registry of N independent RAG corpora; (ii) a way for a caller to address one corpus by NAME on the existing `rag.*`/`edit.*` tools, with omitted ⇒ today's behavior; (iii) per-corpus persistence, import-root, and index isolation so one corpus's failure or ingest cannot touch another; (iv) an operator-visible census. It does NOT inherently require cross-store query fan-out, per-store embedders, hot registry mutation, or an agent-visible store census — those are separable mechanisms the request bundles in.

## 1. Alternatives compared

1. **A — Full five-ask package as one slice (the request as written).** *Weaknesses:* carries B1 (single-file cache with a single-tuple prune contract — `vector-cache.ts:81,181,284-298`, §5.13 pin `unit-f-embeddings.md:2172-2176` would need a shared-prune redesign), B2 (per-store warm-up vs the class-2 sync-before-window abort, `main.ts:159`), B3 (cross-store id collisions + silent default-store mutation), B4 (corpus-relative BM25, `retrieval.ts:263-279`), B5 (unqualified broadcast, `shared/types.ts:359-363`), B6/B8/B12 — at least five unit-sized contract questions inside one "minimal" framing (B11). Unsound as written.
2. **B — Phase-1 core slice (critique's shape, amended by this review).** Registry + pure validation module + `store` selector on all 12 tools + N `createJsonRagStore` instances + per-store engine map + per-store import root + store-qualified broadcast + non-default-store id prefixing + read-only settings listing + migration rule. Per-store embedders, fan-out, hot-apply, active-store UI deferred with their Phase-2 seams pinned now. *Strengths:* every CRITICAL/HIGH blocker is either resolved at its true seam (B3 via id prefixing, B5 via the broadcast qualifier, B6 via the explicit single-store renderer, B7 via a defined per-store surface, B8 via boot-time-only, B10 via the description re-point) or explicitly phase-gated with pinned extension seams (B1/B2/B4/B12). Zero-config stays byte-equal. *Weaknesses:* the dogfooding "query run + main together" use case waits for fan-out; per-store embedders wait for Phase 2.
3. **C — Virtual-store overlay (one physical store, store = a documentId namespace filter).** *Weaknesses:* violates the request's core ask (separate persistence + per-store fail-disabled boot); a corrupt namespace still poisons the single file; quarantine/journal/census are store-global; the `RagStore` interface (SOURCE-SWITCHABLE, `decisions.md:27`) is subverted rather than reused; per-store cache/boot topology becomes impossible without a later migration. Rejected.

**Recommendation: Alternative B** — the only option that preserves the pinned contracts (SINGLE-WRITER-STORE per store, engine-ONCE refined per store, ONE-WAY-SNAPSHOT per store) while closing B3/B5 at their true seams (id minting, broadcast payload) instead of documenting around them.

The name-`main` derivation rule carries over to an EXPLICIT entry named `main` without `persistenceFile`, so the zero-friction registry write `[{name:'main',default:true},{name:'research-2026-09',…}]` preserves all existing data. - **D4 — Store selector contract.** One optional `store` argument on ALL 12 tools (5 `rag.*`, 7 `edit.*` — `security.ts:34-45`). Omitted ⇒ default store. Resolved FIRST, before tool-specific arg validation. Error shapes: `'<tool>: unknown store '<requested-name>''` (echoes only the caller's own input, never enumerates the registry — B9). No new tool names ⇒ the five-seam gate (TOOL_GROUPS, RpcMethod, MUTATING_METHODS, renderer switch, ALL_TOOLS) is untouched — an argument-only change. Cross-store addressing: **per-store id minting for non-default stores at the import seam** — `importMarkdownCorpus` prefixes the documentId passed to `parseMarkdown` with `<name>:` for non-default stores (`markdown-import.ts:120-128`); the default store stays unprefixed (byte-equal). Safe because `sanitizeDocumentId` strips `:` (`markdown-import.ts:47-54`) and the name charset excludes it — cross-store uniqueness is guaranteed, and a foreign-store id passed without `store` misses in the default store (the existing `node not found` fail-state) instead of silently mutating a same-named node (closes B3's CRITICAL mutation hazard). `edit.create_node` mints `n-${randomUUID()}` (`edit-ops.ts:185`) — already globally unique. Result qualification: `RetrievalResult` gains a top-level additive `store: string` (`retrieval.ts:507-519` amendment); `ranked[]` entries stay `{nodeId, score}`. REJECTED: a `store` column on `RagNode` (a hash/journal/store-format change, too large for Phase 1); results-only qualification with no minting change (leaves B3 open).

- **D6 — Vector boot + cache topology (Phase-2 boundary, pinned NOW so no rework).** (a) **Cache topology = per-store files**, one `createVectorCache({ path })` per store (`vector-cache.ts:170-174` supports it), default `provident-vector-cache-<name>.json` with name `main` → the legacy `provident-vector-cache.json`; each store's §5.13 prune stays store-local (keepKeys from ITS store's contents — `vector-boot.ts:284-292`). Error taxonomy Phase 1: `unknown store` (selector), `no rag store configured` (null store, unchanged, `mcp-server.ts:135,371`), plus the unchanged per-tool domain errors. NO store-census MCP tool (enumerates store names to the agent — B9; the census is the operator UI, D9). REJECTED: registry-level abort on a corrupt store (contradicts per-store fail-disabled).
- **D8 — Registry mutation timing (Phase 1).** Boot-time-only: the registry is read once in `main()`; `IPC_OPERATOR_SETTINGS_SET` (`main.ts:361-370`) does not touch it and no `ragStores` field is added to `OperatorSettings`. Editing the registry = edit the JSON + restart. Removal/rename/default-reassignment/hot-apply: out of scope for Phase 1 (each is unit-sized: engine teardown, broadcast rebinding, orphaned-file policy, in-flight-call semantics). ## 4. Change inventory (change-analysis)

1. **New registry file** `provident-rag-stores.json` in userData (D2): boot loads N named stores; validation pins unique names, exactly one default, no two stores resolving to one persistence file, absolute `corpusRoot`s, per-store embedder config REJECTED in Phase 1. 5. **Per-store import root:** `edit.import_markdown` imports into the addressed store using that store's `corpusRoot`; relative `files` paths resolve against the store's root; tool schema stays files-only (ADV-1 discipline); description at `mcp-server.ts:1078` corrected.
6. **Id qualification:** non-default-store imports mint `<name>:`-prefixed documentIds at the import seam; the default store's import output is byte-equal to today's.
7. **Store-qualified broadcasts:** `RagStoreChangedPayload` gains a REQUIRED `store: string`; all four emission sites qualify it; the host drops foreign-store broadcasts before the renderer subscription (the renderer ignores the payload today).
8. **Result qualification:** `RetrievalResult` gains additive top-level `store: string`; `RagQueryPayload` gains optional `store?: string` with preload passthrough.
9. **Failed-store surface:** per-store load states loaded / failed-corrupt (serves empty — today's semantics, per store) / failed-missing (first-run empty); default-store corrupt does NOT block boot; NO store-census MCP tool.
10. **Read-only settings listing** of the stores as provident data in the isolated operator scope via a new IPC channel (IPC-SURFACE-NOT-GROUP-GATED); NO active-store switcher.

## 10. Disagreements recorded (with evidence)

1. **vs critique B3 (visited-set collapse):** overstated for Phase 1 — `assembleContext` is per-store with a per-store visited set (`retrieval.ts:417-444`); the collapse requires a cross-store merged view, which Phase 1 excludes (D1). 2. **vs architecture D4 ("`sanitizeDocumentId` strips `:` so no default documentId can contain it"):** true for documentIds but incomplete — importer **node** ids contain `:` (`markdown-parse.ts:444,565`), and `validateNodeShape` has no charset rule (`rag-store.ts:363`); hence A1.
3. **vs validity ("five-seam gate untouched"):** correct for the gate seams proper, but all 12 tool inputSchemas change (`mcp-server.ts:1067-1078`) and the contract docs + the already-stale §6.2 table must be reconciled (A8) — a real doc cost the "untouched" phrasing could hide.
4. **vs critique B2's "N sequential dark-boot warm-ups is intrinsic":** avoidable, not intrinsic — only the default store needs the sync-before-window warm-up; non-default warm-ups can run concurrently in the background with per-store fail-disabled (D6). B2 still justifies the Phase-2 deferral (cache topology + controller changes are unit-sized), but the cost argument is not a permanent property of the design.
5. **vs the critique's Phase-1 list:** the architecture ADDED U-MS4 (id-prefixing) and U-MS3 (broadcast qualifier) to Phase 1 — without them, Phase 1 ships with B3's silent-default-store-mutation and B5's re-derive storm live in the multi-store configuration, i.e. exactly the configuration Phase 1 creates.
