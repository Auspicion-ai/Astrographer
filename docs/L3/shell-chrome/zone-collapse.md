## 3. The authored-node placement algorithm

Per zone, **after** the container has been written into `children` (both arms — `placementName`-matched repair and the fresh `push`):
```
const mine = (n) => n?.props?.id === `zone-collapse-${zone}`
const dup = children.findIndex(mine)            // idempotence key: the control's OWN id
if (dup >= 0) children.splice(dup, 1)           // never a duplicate; a stray is MOVED, not kept
children.splice(children.indexOf(container) + 1, 0, zoneCollapseControlOf(zone))
```
- **Idempotence key = `props.id === 'zone-collapse-<zone>'`**, never the gutter family's `zone`+`data-axis` pair (`pane-graph.ts:592-600`, `READ`): a `zone`-keyed scan collides with the container and the affordance, which both carry `zone`.
- **Re-assembly over an already-authored envelope:** the scan finds the control and re-inserts it at `containerIndex + 1` — one control, correct adjacency, both stable (graded by the row's `D'`). The container's tab/payload children are still re-appended by the pre-existing merge arm (`:546-554`), so a collapsed zone's strip **doubles** on a second pass: no shipped host path re-assembles an authored envelope, the fix belongs to `U-2`/`U-3`'s merge semantics, and the row grades strip census on the first pass and withholding on both (L1 `§4a` (i)).
- **`placementName` vs `id`:** the `id`-only path replaces the node to synthesize `placementName` (`:542-545`) at the **same index** and keeps its `props.id`; the `placementName` path keeps the node and merges classes. Either way the insertion index is `children.indexOf(<the node just written>) + 1` — recomputed after the write, never the pre-write index.
- **All four zones, empty or not** (limb `D`), in `LAYOUT_PANE_ZONES` order, so the authored order is `container, control, container, control, …` then the gutter affordances.
- **The legacy `zone:sidebar` producer gets NO control** (`:568-583`): the loop iterates `LAYOUT_PANE_ZONES` only and the sidebar block runs after it, untouched.

## 4. The paint rules, selector by selector (G8-only evidence)

1. **The `auto` extent, declarative** — inserted **immediately BEFORE** the F-3 block at `index.html:154-157`:
   `#app > #wiki-root:has([zone='left'].is-collapsed:not(.is-empty)) { --zone-left-track: auto; }` ×4 — **THE `:not(.is-empty)` GATE IS THE MECHANISM, NOT THE ORDER** (corrected in the `G5` repair pass; this rule as designed read `:has([zone='left'].is-collapsed)` and claimed "equal specificity, so the later `0px` wins" — measured WRONG). Both families tie at `(2,3,0)`, so source order decides nothing; the gate makes them mutually exclusive by construction — `auto` requires `:not(.is-empty)`, F-3's `:has([zone='x'].is-empty:not(.is-revealed)){--zone-x-track:0px}` requires `.is-empty` — and the third state (`is-empty` **+** `is-revealed`) matches neither, so the base `var(--zone-<x>-size, …)` fallback supplies the persisted size, the same arm `zoneTrackVars`' `''` removal path hands it. WITHOUT the gate a revealed empty drop target took `auto` on a childless box — zero width, unhittable (the `G5` `BLOCKING` finding). It is the only declarative carrier on the pre-first-write and re-mount path (ASM-U1b-10), and `zoneTrackVars` (§2) is the only carrier after the first inline write, because an inline custom property outranks any stylesheet rule (L2 `F1`).
2. **The arrangement axis** — `#app [id^="zone:"][zone][collapsed='true'][data-orientation='vertical'] { overflow-y: hidden; overflow-x: hidden; }` and the `horizontal` mirror. Keyed on the **authored** `data-orientation` (`pane-graph.ts:549`, the same reading the tab strip's `display` uses at `:243-244`), because "which axis is the arrangement axis" is exactly what that attribute already says; a `[collapsed]`-only rule could not tell y from x. `overflow-x` is pinned hidden in the same rule so a shrink-to-fit `auto` track never grows a scrollbar and stops being content-derived. `overflow: hidden` (not `visible`/`clip`/`display:none`): `visible` paints the strip outside the collapsed extent, `clip` breaks descendant hit-testing, and hiding the container would unmount the `state-slice` mirror's node.
3. **The control's shared box** — `#app [id^="zone-collapse-"][zone] { position: fixed; z-index: 4; box-sizing: border-box; display: flex; align-items: center; justify-content: center; cursor: pointer; background: var(--card-bg); border: 1px solid var(--border); }`. `position: fixed` resolves against `#wiki-root` (`contain: layout`, `:126-132`) — the same coordinate space the zone containers and the gutters use — and `z-index: 4` sits above the gutters' `3` so the control is hit-testable over the affordance's edge.
4. **The four positional rules, off the track tokens, overlaying the zone's foot:**
   `#app [id='zone-collapse-left'][zone]  { left: 0; bottom: var(--zone-bottom-track); width: var(--zone-left-track); height: 20px; }` · `#app [id='zone-collapse-right']` the `right:` mirror · `#app [id='zone-collapse-top'][zone] { top: 0; right: 0; height: var(--zone-top-track); width: 20px; }` · `#app [id='zone-collapse-bottom']` the `bottom:` mirror. The zone's own track token bounds the axis the zone fixes, so the control moves with an `auto`-shrunk zone and its box stays on the zone's foot; the fixed 20 px is the glyph's box on the arrangement axis. No `--zone-*-size` token is consumed (the extent is never read from the remembered size, `G`).
5. **The glyph, by the adjacent sibling on the container's carrier:**
   `#app [id^="zone:"][zone] + .zone-collapse::after { content: '▾'; }` and `#app [id^="zone:"][collapsed='true'][zone] + .zone-collapse::after { content: '▸'; }` — the fork's own glyph pair, re-keyed. The `+` combinator is sound **because** §3 makes the control the container's immediate next sibling, and the state is read from `collapsed="true"` **because** that carrier is the one the model authors (ASM-U1b-9's pair: the class paints the extent, the attribute paints the glyph). The node's `content` stays `''` (limb `D` pins it): a generated `::after` is CSS, not DOM, so D-8 holds.
6. **The collapsed zone's gutter affordance, hidden not deleted** — `#app > #wiki-root:has([zone='left'][collapsed='true']) .gutter[id='zone-gutter-left'] { visibility: hidden; }` ×4. `visibility` and not `display`: `display:none` zeroes `getBoundingClientRect()`, and a zero-area affordance is the **already-recorded defect signature** (`index.html:255-264`, gate-4 finding 8: "the live pass printed zero affordance geometry"), so a future reading could not tell "hidden by contract" from "the box collapsed away again" — the defect behind a green. `visibility: hidden` keeps a real, measurable box while removing the element from hit-testing and the a11y tree; the element stays mounted, so the renderer's delegated `.gutter[zone]` wiring and the host's `gutterZones` identity map (`sidebar-panes.ts:946-960`) need no re-wiring. Correctness does not depend on the paint: `isGutterResizable` refuses the gesture (fail-closed) regardless.
