## 3. The authored-node placement algorithm

Per enabled+placed pane, `paneSubtreeRoot(def, ctx, zone, collapsed)` authors **one frame** with **two children in BOTH states**:

```
frame  props { id: 'pane-'+id, 'data-pane-id': id, collapsed: 'true'|'false' }  classes [pane-frame, (is-collapsed)]
├─ child[0]  head : props { id: 'pane-head-'+id }            classes [pane-head]      (no content, no css.style)
│            ├─ child[0]  grip    props { id:'pane-grab-'+id, tabindex:'0', name:title }  classes [pane-grab]  content '⠿'
│            │             └─ children = LAYOUT_PANE_ZONES.map(z => drop(id, z))          (4, closed, ordered)
│            └─ child[1]  control props { id:'pane-collapse-'+id, pane:id, tabindex:'0' } classes [pane-collapse]  NO content
└─ child[1]  body : props { id: 'pane-body-'+id }             classes [pane-body]
                       children = collapsed ? [] : [renderRoot]
```

- **`renderRoot` is never mutated and never spread onto a node any more** (`READ` `:337-340`: the landed body `{...renderRoot}` made the pane root IS the body). It is the body's single child — one authored level for the sheet's ONE scroller, and the ONLY difference between the two states.
- **No `content` on the head, none on the control, none on the body**; the grip's glyph is the ONE `content` in the bar and its TITLE is `props.name` (limb `a3`). **No `css.style` on the head** (limb `a1`): the head's box is the sheet's, and a `position` there would be a second authority for a fact `C-2` gives the sheet.
- **`data-pane-id` lives on the frame root and the control only** (L2 inv. 10, the landed `zone-collapse-target.test.ts:1442` reading); the head/grip/drops/body carry their own ids, and `props.pane` where they name a record. A new node carrying `data-pane-id` would make the sibling row's frame detector count it as a frame.
- **`collapsed` withholds the body's CHILDREN only** — never the node, never a CSS hide for the CONTENT (that is `ASM-U2-2`'s rejected alternative, which would change what `get_rendered_html`/`get_markdown` expose and would red the landed `unit-live11:465`).
- **Relocation survival needs no code**: `movePane` (`:74-120`) spreads `...p` per entry, so the member travels; limb `E` grades that the DESTINATION frame reads it — which happens **only** because `paneSubtreeRoot` takes the boolean from the assembler's resolved entry (`:220`, `:518`).
