## 2. The one parse, and its answer record

**One judgement, one record, TWO domains, and every level judged** (`display-shape.ts`; contract §2; `paneOf` `view-record/index.ts:544`):

```
displayEntryIn(held):
  not a plain record              -> {ok:false, reason: MALFORMED_DISPLAY_REASON,       message: DISPLAY_SHAPE_MESSAGE}
  a member name outside its LIST  -> {ok:false, reason: MALFORMED_DISPLAY_ENTRY_REASON, message: DISPLAY_UNDECLARED_MEMBER_MESSAGE}
  documentId not non-empty str    -> the member reason, message: DISPLAY_ENTRY_MESSAGE
  caret  stated and unadmitted    -> the same member reason and the same sentence
  view   stated and unadmitted    -> the same member reason and the same sentence
  outside the crossing's boundary -> the same member reason, message: DISPLAY_BOUNDARY_MESSAGE
  otherwise                       -> {ok:true, entry: <the value handed in, minus an own-`undefined` absence>}
```

- **THE ALLOWLIST IS THE FIRST MEMBER ARM AND IT IS WHY `D-23` IS MECHANICAL** (`B1-ADV-01`): `documentId`/`caret`/`view` at the entry, `kind`/`anchor`/`focus`/`focused` in a caret, `path`/`offset` in an edge, `offset`/`section` in a view. A name outside its own list is refused with a sentence that NAMES document content — `content`, `text`, `html`, `title`, `markdown`, `body`, `ragId`, `tabId`, a nested document object — and **never stored, never dropped**. Measured before the fix: all nine parsed `{ok: true}`, were written and were persisted.
- **The order is load-bearing**: a value that is no record is the FAMILY's reason (a payload's shape) and not a member's — `display-admission.test.ts` measures the distinction by IDENTITY of the two `reason` values rather than by spelling either word.
- **Every member is judged only where STATED** (`Object.hasOwn`), and each is refused rather than coerced; **the `path` walk is BY INDEX** (`B1-ADV-02`), because `Array.prototype.every` SKIPS a hole and a sparse `path` rode that skip into the store.
- **THE CROSSING'S BOUNDARY IS THE LAST ARM, AND IT JUDGES THE WHOLE ENTRY** (`B1-ADV-02`, `isBoundary` ported from `view-record/index.ts:527-533` and EXTENDED where the installed release measures more): a cycle (the port recursed to a stack death), a record whose prototype is neither `Object.prototype` nor `null` (`Map`/`Set`/`Date` — `plain` admits them and the crossing does not), an ill-formed string (a lone surrogate), and an array with a hole are all refused here, so a value the store would throw on answers this module's record instead.
- **AN OWN-`undefined` OPTIONAL MEMBER IS THE LAWFUL ABSENCE** (`B1-ADV-16`): `{documentId, caret: undefined}` is the ordinary optional spread's result and is ADMITTED; the admitted entry spells the absence by not carrying the member, because the crossing refuses `undefined` and the parse cannot hand one on. This is the ONE normalisation the parse performs — everywhere else the admitted answer IS the value handed in, which is what makes the row's deep equality the sharpest reading of "never coerced".
- **TWO tokens, FIVE sentences, all exported**, so a row reads them off the module (`D-43`): the member domain keeps ONE sentence for out-of-domain values (that identity is the "one parse, one voice" property) and gains two more for the two faults a caller must be able to tell apart — an undeclared NAME and a value outside the crossing.
- **`displayEntryMemberAdmits(member, held)` is the same parse's members, one at a time, and it JUDGES THE NAME**: `documentId`/`caret`/`view` by domain plus boundary, **anything else `false`**. It exists because a THIRD segment is reachable (L2 §7's `F-R2`): without a name judgement there, a member off the allowlist would land under a standing entry by a route no `commitTab` ever takes.
- **`displayPlaceholder()` = `{}`**: one plain record at the root, stating no tab. It is a FAMILY value and not an entry, so the entry parse refuses it — the distinction the row asserts.

## 3. The family object, the constraint, and the repair's measured write route

- **The spec is `tag`-discriminated** and the discriminant is what closes the omission: `paired` requires `id` + `body`; `unpaired` declares both as optional `never` (the `?` is load-bearing in both directions). `displayFamily` builds `root` once and defers the body factory to `declaration(getStore)`, once per call — `FH-3 (d)` counts that with a fixture it owns. **`declaration` answers `null`** when unpaired, and the projection is the one place that tests it.
- **AND THE `tag` HAS A RUNTIME DOMAIN TOO** (`B1-ADV-09`): a tag that is neither literal THROWS a `TypeError` from `displayFamily`. Measured before the fix: such a spec published a root with `declaration: null`, no creation repair ran, and **every write answered `AddressNotFound`**. This is a DELIBERATE divergence from the design source's silent degradation, recorded at L2 §7 `F-R5`.
- **The constraint `display-must-stand`, one declaration at `['display']`, four arms in the foundation's order** (`panesMustStand`, `:1047-1067`):

| # | Instant / node | Answer |
|---|---|---|
| (1) | root, value not a plain record (registration included) | `{message, repair: repairDisplay}` — the placeholder, through the module's ONE repair-write path |
| (2) | root, value a record naming an entry the parse cannot state | **REFUSED** `{message}` with NO REPAIR, **at a write instant only** (`writeInstant`: `context.tier` non-null) — at a registration instant it answers `true`, because a corrupt profile's BYTES must not refuse the construction |
| (3) | a tab id: the landed value is ONE entry | the whole entry — allowlist, every member's domain, the boundary — refused at a write instant, never repaired |
| (4) | a member's own node (`['display', <tabId>, <member>]`) | the member's NAME and its VALUE, refused at a write instant, never repaired |

- **WHAT `D-105`'S ARM ACTUALLY REACHES, WHICH IS EASY TO OVER-READ** (`B1-ADV-03`): the body judges `context.value` at the node the act's ADDRESS names, so (2) is the root's, (3) the tab's and (4) the member's — **it never sees a sibling**. That is enough for the claim it must carry: no write THIS MODULE routes can leave the store holding a member the read cannot state. What it does NOT reach is a member an OUTSIDE writer left (an older image, a second process, a store built without the pair), and there the arm that answers is the READ's — see §5.
- **THE THREE INSTANTS ARE THREE DIFFERENT RECORDS, AND NO ONE IS "THE OTHER PLUS A MEMBER"** (`RUN`, measured at the installed release by counting the record's own members as each arrives):

| Instant | Members the record carries | Route |
|---|---|---|
| the CONSTRAINT BODY, at any instant | **5** — `{address, tier, value, attempt, op}`, **no `write`** | `true` / `{message, repair}` / `{message, repair?: never}` |
| a REGISTRATION repair | **7** — `{address, id, tier, value, op, pending, write}` | `write(address, tier, value)`; a fourth position throws `TypeError` **before any store act** |
| a LANDING repair | **6** — `{address, id, op, tier, value, pending}`, **no `write`** | `store.write(address, tier, value, context)` — the fourth position JOINS the asking commit |

  So `repairDisplay` branches on the record's own `write` member and never on the instant's name: `write` present → the three-position route, answering `{ok: true, op: receipt.op}` — **THAT write's own op**; no `write` (a landing) → the joined write; neither → the **stated** failed arm `{ok:false, message}`, never a silent one.
- **The construction sequence, measured** (`RUN`, one fresh instance): the body is asked **three** times — the registration's first ask with `value: undefined` and `tier: null` (arm (1) fires), the repair-write's own landing instant with `value: {}` and `tier: 'file'` (arm (2) passes), and the registration's **RE-RUN** with `tier: null` (passes) — one repair, **one delivery of `['display']` to the adopted listener, arity 1**. A repair that credits no op, or whose re-run still refuses, is refused at the construction (`ConstraintRefusedAtRegistration`) and after it landed (`ConstraintPassRefused`); both arms were DRIVEN and neither is reachable here.
- **The landing repair is reachable and was measured**: with the family deleted, a root write carrying a non-record lands the caller's value, the pair's repair takes arm (2) and the family ends as the placeholder.
- **What the contract's "at or below a tab id" means at the store's address domain**: a write at `['display', <tabId>, <member>]` LANDS when the entry stands, and one below a non-record parent refuses the store's own `WriteParentNotLink`. Both are measured. **AND A BOUNDARY-HOSTILE VALUE NEVER REACHES THE PAIR AT THAT DEPTH** (L2 §7's `F-R6`): the crossing refuses it first with `ValueRefusedAtBoundary`, so the reading there is "refused, and nothing landed" rather than "the pair refused".

## 4. The delivery: entry shape, handle minting, a fan-out that COALESCES

- **`{address, handle, listener}` — three own members, the THIRD REQUIRED**; a two-member element is refused `AddressMalformed` before any filesystem act (`RUN`). The entries are built from the module-private `DISPLAY_DECLARED_ADDRESSES = [DISPLAY_ADDRESS]`, **which is NOT derived from the family tuple** — that independence is the whole of what `FH-1`/`FH-2` compare.
- **The handle is minted by a module counter**: `'record-engine:' + ordinal + '@' + address.join('/')`. The ordinal is what stops `register`'s replacement and `unlisten`'s whole-withdrawal from starving a second subscriber, and the fixed prefix is what keeps a handle from ever equalling a constraint `id`.
- **The body, in order and with two guarantees**: one PASS — walk a COPY of the handler list, each call contained on its own, **arity 0** — and **then** the sink with one argument, the triggering address. The whole body is wrapped so the sink's throw stops there (an uncontained one refuses a construction at rank 21 `ListenerBodyThrew`).
- **A NESTED DELIVERY IS COALESCED, NEVER RECURSED** (`B1-ADV-08`): while a pass is in flight a further delivery sets a pending flag and remembers ITS address; after the sink the outer fan-out runs **ONE more pass** at that address, and any nesting during that pass is dropped — correct rather than lossy, because the push is a signal whose answer is the consumer's own re-read (`D-82`), and the re-read has not happened yet at that depth. **The bound is two passes for any number of writes**; measured before the fix: `358` passes for a subscriber that wrote once per delivery and `381` for one that wrote 380 times, with a `RangeError` inside the fan-out that the body's own containment made invisible.
- **The delivered address is the LEAF** (`RUN`: a write at `['display','tab-a']` delivers `["display","tab-a"]`, one argument), so a consumer routes on a prefix and never on equality with the root; **the client never sees an address at all**.
- **`subscribe(handler)` hands its handler nothing and returns a local, idempotent withdrawal** that runs no store verb — the registration is the construction's.

## 5. The record, and the client

- **`read()`/`readTab()` are TOTAL over a store that THROWS on an absent address** (`RUN`: `AddressNotFound`): both catch and answer `null`, because a read writes nothing and an absent family is a declared absence, never a fabricated placeholder.
- **AND A FAMILY IT CANNOT STATE WHOLE ANSWERS THE DECLARED ABSENCE** (`B1-ADV-03`, `D-105`'s arm at the read): `read()` builds a FRESH plain record only if EVERY member is one the parse states, and answers `null` otherwise; a prototype-key member is in the same class, since it is the reading's key space and no tab states it. **The drop is gone** — measured before the fix: a family holding one unstatable member read back as the statable members only, silently, while the store still held the member. A statable ROOT write replaces the family and the read answers again (`root-invariant.test.ts` measures both halves).
- **`commitTab(tabId, entry)` is shape arm → the parse → then ONE leaf write** at `['display', <tabId>]` on `DISPLAY_TIER`. **THE SHAPE ARM HAS TWO DOMAINS**: an id that is no non-empty string, and an id that is a PROTOTYPE key (`__proto__`, `constructor`, `prototype`) — the second measured as a member that committed, vanished from `read()` and became the reading's PROTOTYPE while `readTab` still answered (`B1-ADV-05(a)`). `DISPLAY_WRITE_EVENTS` is the pinned three-event cadence: one whole-entry write per EVENT.
- **`createDisplayClient(port)`**: `fill()` is the one stated read and **answers the reading that stands after the call**; `reading()`/`displayOf()` are synchronous off the held shape and cost the port nothing; **`subscribe`'s listener re-reads INSIDE itself**, REPLACES the shape and hands the caller that reading.
- **THREE HOLDING RULES, EACH A MEASURED FAULT FIRST** (`B1-ADV-04`, `05(b)`, `05(c)`): **only a READING changes the shape** — no route, a throw, a rejection and a value that is no plain record all leave the standing shape INTACT, because a failure is not an absence and the client cannot tell "the family is gone" from "the read failed"; **the latest-STARTED fill wins** (a monotonic counter taken at call time, so two overlapping fills end on the newest rather than on the last to resolve); and **`displayOf` reads OWN members only (`Object.hasOwn`) and hands an entry out only through the family's parse** — `displayOf('__proto__')` used to answer `Object.prototype` and `displayOf('constructor')` a function. Every read of a port MEMBER is inside a `try`, so a getter that throws is the absent route it is.
- **The four absent arms are four words, in the order the faults are reached**: `no-port` → `no-read-route` → `no-changed-route` → `register-threw`, each with a total `release`. A port missing BOTH routes is the READ route's arm: a subscription that registered there would promise a re-read it could never perform.

## 7. Readings, the finding this design WITHDREW, and the two it refined

- **`FH-3 (e·refused)`'s instrument is reachable and GREEN**: the `tsc --noEmit --strict --skipLibCheck` subprocess over `spec-shape.fixture.ts` answers exit 0 with all five `@ts-expect-error` directives intact.
- **`F-R1` — WITHDRAWN AS FILED, AND REPLACED BY THE CORRECTED READING.** As filed it said three battery rows could not be satisfied by any implementation and left them red. **The corrected reading: the store CANONICALISES member order** (sorted, recursively, at all three tiers, and in the op's `after.value` — `RUN`: `{zeta, alpha, mid}` reads back `{alpha, mid, zeta}`), **and that stays a PACKAGE finding** for `docs/defects.md`. - **`F-R2` — the "at or below a tab id" arm is REACHABLE**, and this design refines it rather than restating the contract: depth 2 lands under a standing entry, depth 2 under a non-record parent is the store's `WriteParentNotLink`, and only depth 4 is out of the store's address domain. - **`F-R3` — `F-3` is answered by measurement** (`15` members, `14` symbols at construction, `RUN`), and the seam's docblock carries the figures and their arm.
- **`F-R4` — the renderer takes the parse by VALUE** (recorded at L2 §5 and §7), a disclosed divergence from the contract's `import type`, because a second spelling of "an entry" in the client would be a second authority for the family's shape; the `src/shared/` carrier is `B-2`'s.
- **`F-R5` and `F-R6` complete the set** (L2 §7 carries both with their measurements): the `tag`'s RUNTIME domain is a thrown `TypeError` (§3 above), and the crossing answers a boundary-hostile value BEFORE the constraint pass, so at a member node the reading is "refused, nothing landed" rather than "the pair refused" (§3's last bullet).
