## 3. The pane's subject — `ASM-B5-1`, and it is the unit's one design call

- **Decision:** the `crosslinks` pane is about ONE node, `linksPaneSubjectNodeId()`: **`_currentNodeId` when it is set (unchanged behaviour for any future producer), else the CURRENT DOCUMENT'S DOC-HEAD NODE**, read from the cached traversal snapshot's `doc-head` edges (`kind === 'doc-head' && target === _currentDocumentId` → `source`; `READ` `src/main/traversal.ts`'s doc-flow vocabulary, `src/main/backlinks.ts` `documentOf` `:47-64`'s own reading of it). `null` when no document is current — the pane then renders `(none)` and the paint answers `unchanged`.
- **Why this subject and not a new selection seam:** the pane's OTHER half is already document-scoped — `ctx.crosslinks` is `buildTraversal`'s **outgoing-only** wiring over the *materialized* nodes (`READ` `traversal.ts:562-570`, `pane-registry.ts:37-39`), so a pane whose outgoing half is "the rendered document's crosslinks" and whose backlink half is "one node" is only coherent if that node is the document's own head. The head is host state already (`lastSnapshot`), needs no new IPC and no DOM read.
- **Rejected alternatives:** a node-selection producer (a new UI seam, no ruling asks for it, and `provident.focus` already exists for the MCP surface); making the pane's subject a document (the enumeration is per-NODE, `backlinks(nodeId)`); reading the subject off the rendered DOM (the host reads no DOM).
- **The ONE line this costs `refresh()`**: `refresh()`'s backlink fetch uses **the same helper**, so the pre-migration route and the paint agree about what the pane is about — two authors for one subject would be the `ASM-B3-2` fault one level down. Its guard semantics are unchanged (`null` ⇒ no fetch). **`F-2` is thereby closed for the pane's data without a second definition of "its node".**
- **`ASM-B5-4` — THE SUBJECT NEEDS AN INVALIDATION RULE, and the first landing had NONE: it is this unit's ONE HIGH finding and it is FIXED here, not carried.** As filed, the subject was re-read ONLY on a fire, so (a) a document switch — `setCurrentDocumentId`, a bare assignment — re-read NOTHING and the pane re-authored the PREVIOUS document's backlink line under the new one, and (b) a `rag.backlinks` answer landing AFTER the subject moved was COMMITTED and PAINTED (the superseded subject's enumeration). **⟨MEASURED (`B5-ADV-05`/`-06`): a driven document switch read `0 refresh()`, `0 backlinks`, and the identical authored line before and after; a deferred answer resolved after a move painted `{painted:true, applied:['pane-crosslinks']}` with the OLD subject's line.⟩** The fix, as landed: **(i) a SUBJECT STAMP** on the re-read — the subject is captured before the `await` and RE-RESOLVED after it, and a mismatch DROPS the answer (no commit, no paint) — spelled with the host's OWN `pageSubjectStamp`/`superseded()` idiom, no second invalidation vocabulary; and **(ii) a FIRE FROM BOTH SETTERS, only on a real move** — `setCurrentDocumentId`/`setCurrentNodeId` compare the resolved subject before and after the assignment and fire `crosslinks` only when it MOVED (a same-value call fires nothing, which is the row's discriminating control, and the fix must not amplify). The boot's initial selection deliberately does NOT fire (no census subscription exists and no frame is authored yet); **that hunk is measured, not stylistic — routing boot through the firing setter red the `L9` pin with `dispatched -1 fire(s)`.** *Rejected:* re-reading on every re-derive (an IPC on the app's content path, and `ASM-B5-3`'s traversal argument again). **`ASM-B5-4(c)` is CARRIED, not closed:** a `rag.backlinks` that NEVER settles still starves the paint — `invoke`-hung bridges are the bridge's defect, and no timer is admissible (`D-82` clause 4).
