## 1. The unit, and the five `READ` findings that decide its shape

**The act (the map's row, verbatim):** *"`search` + `template-editor`: a template change repaints the template pane alone; a query result repaints the search pane alone"*, and *"the advanced-search carrier survives"*. Both panes join `REPLUMBED_PANE_IDS`, so from here every update of either answers `INV-E` — **0 `loadAppGraph` / 0 `mountOperator` / 0 `refresh()`** — and every other family keeps its `refresh()`.

- **`F-1` — THE SEARCH PANE'S DATA IS THREE HOST FIELDS AND NOTHING READS THEM BUT ITS OWN RENDER.** `searchContent(ctx, this.lastQueryResult, { expanded: this.advancedSearchOpen, documentFilters, error: this.advancedSearchError })` (`READ` the pane's registration in `registerPanes`; `READ` `pane-graph.ts`'s `searchContent` — every input it authors comes from `result`/`options`, and `ctx` is not read at all). `grep` over `src/**`: `lastQueryResult` = the declaration, the render and the TWO commits (`submitQuery`, `submitAdvancedQuery`); `advancedSearchOpen` = the declaration, the render and `searchAdvancedToggle`; `advancedSearchError` = the declaration, the render and those same two producers. **No other pane, no assembly and no traversal reads any of the three** — so a re-assembly for this pane's data re-authors the WHOLE app to move one root.
- **`F-2` — TODAY A SETTLED QUERY RE-ASSEMBLES THE WHOLE APP GRAPH, and that is the defect this unit removes.** `submitQuery`'s settlement commits `lastQueryResult` and then calls `this.loadAppGraph(this.runtime, this.lastTraversalEnvelope)` behind `if (this.editController.anyDirty()) return`; `submitAdvancedQuery`'s `rerender()` is the same call in both its arms. `READ` `loadAppGraph`: it assembles the pane-inclusive envelope and calls `runtime.loadEnvelope` (tearDownGraph → a fresh render), so **every** pane frame and the page surface are re-minted for one pane's data. `searchAdvancedToggle` and `templateValidateResult` instead call `requestRebuild()` (→ `reDerive('content')` → `applyContentChange`), which re-authors roots this pane does not own.

- **`F-4` — THE TEMPLATE STORE'S PUSH ALREADY CARRIES THE WHOLE TEMPLATE, so a `template.get()` re-read would be an IPC that can change nothing.** `TemplateChangedPayload { source, template }` (`READ` `src/shared/types.ts`, its own docblock: *"Payload carries the current template so the renderer re-derives without a follow-up fetch"`), broadcast on `IPC_TEMPLATE_CHANGED` by main's `handleTemplateIpc` (the IPC route) and by `handleTemplateTool` (the MCP route). `READ` `onTemplateChanged`: it commits `this.template = payload.template` today and only ever fails to paint the PANE.

## 2. The two sources, NAMED, and what each may reach

- **`search` — its OWN answer, and no other source.** The producer is `bridge.rag.query` reached through the two submit seams (`submitQuery`, `submitAdvancedQuery` — the app's own `window.provident.sidebar` surface, `READ` `installSidebarBridge`), which COMMIT `lastQueryResult`/`advancedSearchError` and then **FIRE** `search`; `searchAdvancedToggle` fires too (the disclosure is the pane's own state). **REFUSED, with the reason: a local store-change source for this pane.** `onRagStoreChanged` cannot be its producer: nothing in the pane's data is store-derived (`F-1`), so a fire there could only be answered by a WHOLE-STORE read (`snapshot`/`docHeads` — refused: the pane does not render them) or by a re-issue of the pane's own query — and a re-issue on a fire is an **UNBOUNDED LOOP**, because the re-issue's own settlement is itself the producer that fires (`query → fire → query → …`). The channel is payload-free by construction (`ASM-B3-2`), so the handler cannot tell a settlement fire from a store fire; the loop is therefore structural, not a discipline. The pane's freshness is not reduced by this refusal: any content re-derive still re-authors it from the committed result, exactly as today.
- **`template-editor` — the template STORE's change, twice over.** The source is `bridge.template.onTemplateChanged` → `TemplateChangedPayload` (main's `IPC_TEMPLATE_CHANGED`, §1 `F-4`), whose handler commits `this.template` and FIRES; and the pane's own validate seam (`templateValidateResult`, the verdict `bridge.template.validate` answers) commits `this.templateValidation` and FIRES. **`src/renderer/template-pane.ts` owes ZERO byte:** its render is already pure data over `buildTemplateContext()`'s host state, so every input the paint changes is host state (the `B-5` §5 precedent).
- **The discriminator between the two panes' sources is the ENTRY, not a payload:** the two arms are reached by two DIFFERENT call sites on ONE registry, and neither can reach the other's registration (`fire('search')` cannot run `template-editor`'s handler). **Neither pane joins `CHANGE_INTERESTED_PANE_IDS`** — no engine frame can change a query answer or a stored template, and `changePanes()` stays exactly `['doc-nav']` (`X2`).
