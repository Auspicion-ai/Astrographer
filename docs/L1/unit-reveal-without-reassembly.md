## 1. The defect, confirmed; the two candidates; and the choice

- **THE ROOT CAUSE, CONFIRMED (not re-diagnosed).** The drag reveal is applied by `onRevealChange` → `this.revealedZones = [...zones]; this.rerenderAppGraph()` (`READ` `sidebar-panes.ts:929-932`), and `rerenderAppGraph` is `applyZoneTracks()` **then** `loadAppGraph(...)` → `runtime.loadEnvelope(...)` (`READ` `:3834-3844`, `:2025`) — a FULL re-assembly that destroys and re-mints the `.pane-frame` nodes. The gesture's pointer capture is held on one of those frames, so the browser fires `lostpointercapture`, `renderer.ts`'s document-delegated guard (`READ` `:1151-1159`, wired at `:1269-1275`) turns it into `cancelPaneDrag()`, and the session's terminal never reaches `commitPaneDrop` — so all five terms read false. `RECORDED` mechanism and readings: `docs/defects.md`'s row + `docs/L1/unit-u-3-pane-move.md` §7a, measurer the `U-3` scoped live leg (`gotpointercapture=1` → `lostpointercapture` on `DIV:doc-nav`, six later moves reading an empty reveal mirror).
- **WHY THE WITHIN-ZONE LIMB IS GREEN, stated exactly, because it is the fix's own regression control.** A within-zone rearrangement DOES reveal (the pointer is inside the source box, `distance = 0` ⇒ `measuresWithinSnapThreshold` admits it, `READ` `pane-drag.ts:343-355`), so it re-assembles too — but its reveal set changes exactly **once**, from `[]` to `['left']`, on the FIRST move of the gesture, and the capture is not yet claimed then (`onPaneSessionMove` claims only past `PANE_DRAG_CAPTURE_THRESHOLD` of travel, `READ` `renderer.ts:763-786`). The claim that follows resolves the **LIVE** frame by pane identity (`captureTargetOf()`), so it survives. The cross-zone drag's second transition (`['left']` → `['left','right']`) happens late, when the capture is already held — that is the whole defect, and it is why a repair must remove **every** reveal transition's re-assembly, not just the first.
- **CANDIDATE (a) — CHOSEN: apply the reveal WITHOUT re-assembling**, through the mechanism the corpus already names and the fork already ships, in three landed parts: **(i)** the TRACK half, `applyZoneTracks()` (`READ` `sidebar-panes.ts:1634-1675`) — the inline `--zone-<z>-track`/`--zone-<z>-size` projection whose `''` removal path hands a REVEALED empty zone the stylesheet's `var(--zone-<z>-size)` fallback (`READ` `index.html:119-120` + the `:has(...:not(.is-revealed))` gate at `:192-195`); **(ii)** the CLASS half, the managed `state-slice` mirror write the fork already uses for exactly this family — `syncZoneMirrors` (`READ` `sidebar-panes.ts:2275-2321`) writing `{ targetProp: 'css.classes', mode: 'replace' }` on `zone:<z>` through `runtime.applyCommand` (`READ` `runtime.ts:748-851`, the `clientAPI.apply` normalisation at `:796-806`), whose landed purpose is *"pane-additive, no `loadEnvelope`/teardown, stable `zone:*` identities"* (`READ` `:2103-2111`); **(iii)** the ONE author both halves read, `zoneMirrorClasses(paneCount, collapsed, revealed)` (`READ` `pane-graph.ts:605-611`, today private) — so `is-empty`/`is-collapsed`/`is-revealed` keep ONE spelling and the assembler and the paint cannot disagree (the `ASM-U1b-10` precedent: one predicate, two carriers). **The pointer capture is never touched because the frame is never replaced; the reveal is authored THROUGH the engine, so it stays visible to `get_rendered_html`/`dispatch` (D-8) — no hand-written DOM, no `classList` poke.**
- **CANDIDATE (b) — ARGUED DOWN: defer `loadAppGraph` while a gesture holds the capture** (a queue replayed at the gesture boundary). Five reasons, in order of weight: **(1) it does not deliver the behaviour.** With the re-assembly deferred, the destination zone is never `is-revealed` and its track stays `0px` DURING the drag, so term (iii) `theDestinationZoneOpened` stays false and the operator gets no drop preview — the affordance the preview band exists to provide, and the exact class of defect the operator has already filed twice (`GUTTER-RESIZE-NO-LIVE-VISUAL-FEEDBACK`, `PANE-DRAG-CROSS-ZONE-DROP-UNSUPPORTED`). To pass the five terms (b) must still paint mid-drag, i.e. it must contain (a) and add a queue on top. **(2) It inverts the layering.** "A gesture holds the capture" is a fact only the RENDERER owns; the host owns the record and the reveal set. (b) forces a new renderer→host signal and a latch whose clearing path can be missed — the measured shape of `PANE-HEADER-DRAG-NEVER-COMPLETES`' root cause (2): *"one gesture that never reaches a terminal can latch every later pane drag"* (`docs/defects.md`). **(3) Its invariant debt.** A queue replays at the boundary, so the crossing-N-times law (D-266, `U-3` limb `H`) would have to reconcile queued writes with the ONE write; (a) adds nothing to reconcile — the reveals stay mirror-only and write nothing to the record. **(4) It leaves the mechanism that broke in place**, so the defect survives as a latent hazard for every other trigger. **(5) TRIGGER-REACHABILITY — the decisive cost, as asked:** a later unit that gives the reveal another trigger (a hover, a keyboard arm, the D-24 event-driven update path, `U-4`'s own re-render sites) inherits the bug under (b), because (b)'s safety is a property of ONE trigger's identity (a pane gesture holding capture) and the new trigger is not that gesture. Under (a) the reveal path carries no re-assembly at all, so **every** future trigger is safe by construction.
- **WHAT (a) COSTS, named rather than hidden.** **(c1)** A second caller of the mirror write — the class half now has TWO callers (the content reconcile and the reveal paint) instead of one; they are kept from drifting by (iii)'s single predicate, not by discipline. **(c2)** The reveal no longer produces a fresh envelope, so any consumer that read the reveal off a re-assembled graph must read it off the LIVE node state (`nodeState('zone:<z>').states[0].css.classes`) — nothing in `src/**` does today (`READ`), and the state is in the graph either way. **(c3)** The paint runs a bounded pure computation per reveal TRANSITION (never per frame — the controller writes only on a set CHANGE, `READ` `pane-drag.ts:442-459`), which is strictly cheaper than today's assemble + `recomputeBackRefs` + `loadEnvelope`. **(c4) THE RESIDUAL, stated so it is not read as closed:** a re-assembly arriving from ANY OTHER source mid-gesture (the settings broadcast, a content refresh, a registry change) still replaces the frame and still ends the gesture. (a) closes the REVEAL as a re-render site; it does not make the gesture survivable across arbitrary re-renders. That hazard is named here, ownered by the unit that next puts a re-render on the gesture path (D-24's migration is the likely owner), and **not** papered over with a deferral latch — which is why (b) is refused rather than shipped as a belt.
- **Rejected:** (b), above. **Rejected:** raising any `z-index` to keep the frame hittable — no box moves in this unit and the shell's gear stays the ceiling (`READ` `index.html:286-288`: `z-index` is deliberately NOT raised above `#settings-toggle`'s `110`; if a box must move, the box moves). **Rejected:** re-deriving the reveal's paint from a new second author in `renderer.ts` — `renderer.ts` owes **no byte** here: its capture claim, its terminal routing and its lost-capture guard are all correct once the frame survives.
