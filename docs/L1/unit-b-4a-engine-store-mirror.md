## 1. The unit, and the defect VERIFIED before it is fixed

- **The defect, as four `READ` clauses and not as a report:** the doc-heads read is `handleRagDocHeadsIpc(runtime.getDefaultStore())` (`READ` `src/main/main.ts:1136-1138`) and it answers from `doc-head` edges + node content of **one local `RagStore`** (`READ` `src/main/mcp-server.ts:910-941`, the edge at `:912` the head node's `content` at `:934`); the engine write path is two wire clients that hold **no store at all** (`READ` `src/main/engine-rag-store.ts:860-1107`, `src/main/engine-crud-rag-store.ts:662-780`) — `crudCall` decodes the accepted answer and returns it (`READ` `:726-728`, `return crudResult.result as T`); and the only writers of the local store are the local edit path (`READ` `src/main/edit-ops.ts`'s `putNode`/`putEdge` sites), markdown import (`READ` `src/main/markdown-import.ts:387`) and the IPC batch (`READ` `src/main/edit-ops.ts:447`). **So the engine's writes reach nothing the doc-heads read: the pane re-reads and answers `unchanged`. `B6-F1` is CONFIRMED, and the consumer is not wrong — the path is incomplete.**
- **The act:** one module, `src/main/engine-mirror.ts`, that makes an engine-originated write **visible** in the store the doc-heads read, and nothing else. It paints no pane, declares no pane interest, emits no descriptor, adds no channel, opens no second engine client, and re-assembles nothing.
- **What it is NOT (`ASM-B4A-1`):** the engine stays authoritative for engine-side data. The mirror's content is a **PROJECTION** of an answer the engine gave — never a local decision, never a copy of the engine's graph, never a second source of truth for a document.

## 2. The route — chosen, argued, and what it costs

- **THE ROUTE IS BOTH OF THE GRANT'S ARMS, CONVERGED ON ONE PROJECTION: the engine CRUD surface's ACCEPTED WRITE (§1 limb (a)) and the change descriptor (§1 limb (b)), each calling the same projection function.** Limb (a) is the spine and limb (b) is the completion; neither alone is lawful, and that is this unit's central argument:
  - **(a) ALONE IS INCOMPLETE.** An engine write that the fork did not issue — another client, or the engine's own re-derivation — never passes through `createEngineCrudRagStore`, and the engine is authoritative for exactly that data (`ASM-B4A-1`). A mirror that only the fork's own writes drive would answer `unchanged` for precisely the case `B6-F1` names, "engine-ORIGINATED".
  - **(b) ALONE IS DEAD AT THIS HEAD, AND THAT IS MEASURED, NOT ARGUED.** The descriptor arrives from `GET /changes`, and the adjacent `../Gnosis` build refuses the fork's stream client (`sse: non-2xx` — `docs/defects.md:36`, `D-36`/`D-37`, §8 below). A descriptor-only mirror would therefore never run in the shipped app; worse, the fork's OWN accepted engine write (the one path that can be proven at node grain today) would stay invisible.
  - **AND THE DESCRIPTOR CANNOT CARRY THE DOCUMENT.** `RagStoreChangedPayload` is four members (`READ` `src/shared/types.ts:415-421`) and the engine's `nodeIds` are the entry's **graph node ids** (`READ` `../Gnosis/src/store/mod.rs:1225-1266`, `node_ids_of(graph)`; a document's own `document_id` is not in that set) — so limb (b) is a **TRIGGER**, never a payload: it tells the mirror the engine's store moved, and the mirror answers with the engine's authoritative **document list** read (`ASM-B4A-2`). Anything else would make the mirror guess a document from a node id.
- **What the route costs, stated rather than implied.** (1) **One local batch write per projected change** — through the store's OWN single writer, so it journals and it persists once; the mirror never introduces a second writer (§5). (2) **The fork's own mutating engine call now waits on one local batch** before it resolves — the price of "the same instant" limb. (3) **One bounded engine document-list walk per structural engine descriptor**, coalesced to one-in-flight plus one trailing (§4), and **one duplicated walk per connect** (the feed's `reconcile` walks, then its own answer is a descriptor like any other — `ASM-B4A-3`'s rejected alternative is an identity handshake the wiring census could not read). (4) **The projection carries what an engine answer carries**: title, id, tags on the limb-(a) path, id + title only on the limb-(b) summary path, and **no path/tags from the list** — named, not smoothed.
- **Rejected, with the reason each time:** *(a) alone* — misses the origin the unit exists for; *(b) alone* — dead behind the parked feed and cannot name a document; *(a third route: the local store as a cache of the engine's graph)* — copies the engine's graph into a store whose reconciler would then walk a stale graph, i.e. the second source of truth `ASM-B4A-1` refuses; *(mirror inside `handleGnosisTool`)* — `src/main/mcp-server.ts` is outside this grant, and a mirror hung off the tool handler would miss every caller that is not that tool.

## 3. The module's I/O surface (names and behaviour are this contract's; signatures are L2's)

- **`src/main/engine-mirror.ts` (NEW), ONE runtime export `createEngineMirror(opts)`** returning a handle of **four members**, plus its types:
  - **`accepted(write)`** — limb (a). Called by the engine CRUD proxy **with the answer the engine accepted**, before that proxy's own call resolves. Two declared writes: an **upsert** (a `Document` the engine answered) and a **remove** (the `documentId` of a `deleteDocument` whose answer is void). ASYNC; its fault is **contained** — the engine has already accepted the write, so the caller's answer must not become a failure; the fault is counted and named on `status()` instead.
  - **`settle(descriptor)`** — limb (b), **the ORDERING POINT**: for an engine-origin `structural` descriptor it brings the projection up to date with the engine's **document list** and resolves **before** the caller broadcasts; for a `content` descriptor, for a foreign origin, and for a descriptor that names nothing it is a counted no-op. ASYNC, **serialized** (one settle at a time, and the walk coalesces: a descriptor arriving mid-walk sets a trailing demand that runs ONCE when the walk ends — no timer, no interval, no re-arm).
  - **`reconcile()`** — the feed's `reconcile`: it **walks the engine's document list, projects every document it sees, and answers the four-key engine-origin descriptor** naming them. So the re-read's answer and the projection are one act, which is invariant §5 limb 1 by construction rather than by agreement.
  - **`status()`** — a COPY: the projections held, a **closed** count set (`accepted · projected · unchanged · removed · refused · unresolved · failed · walks`), and the last typed failure or `null`.
- **`opts` (four members, all injected — the module holds no host, no Electron, no fs, no socket, no clock, no timer):** `store` (**a THUNK**, not a store: the shell's hot default-store swap must be honoured, `READ` `src/main/rag-store-runtime.ts:710`), `read` (the engine document-list read — main.ts owns the bounded, paged walk its `F-4` finding already requires, so the walk does not move into this module), an optional `origin` (defaults to `ENGINE_ORIGIN_STORE`, `READ` `src/main/engine-rag-store.ts:90`) and an optional bound on how many ids one walk may project.
- **`src/main/engine-crud-rag-store.ts` — the accepted-write seam only.** `EngineCrudRagStoreOptions` gains ONE optional member (the sink) and `crudCall` calls it **once, after** `decodeCrudResponse` returned — i.e. **only for an answer the engine ACCEPTED** — for the SIX mutating document methods (`createDocument`, `updateDocument`, `deleteDocument`, `publishDocument`, `unpublishDocument`, `archiveDocument`). **Reads never fire it** (`getDocument`/`listDocuments`/`getWiki`/`listWikis`/`createWiki`), and a refused call (any `EngineWireError`, any malformed body) never fires it. No other byte of that file moves.

## 4. The two triggers, and the ORDER is the whole of the invariant

- **Limb (a)'s order: the projection lands BEFORE the engine's answer reaches the caller.** A caller that has the engine's answer can already re-read the doc-heads and see it; nothing between them is asynchronous.
- **Limb (b)'s order: the projection lands BEFORE the descriptor is broadcast.** `src/main/main.ts`'s sink is the ONE broadcast site (`READ` `main.ts:893`, `onChange: (descriptor) => backend.broadcast(IPC_RAG_STORE_CHANGED, descriptor)`); it becomes **mirror, then broadcast**, and `settle` serializes, so broadcast order stays frame order. A pane that reacts to the descriptor by re-reading `IPC_RAG_DOC_HEADS` therefore cannot read a store the mirror has not yet written — **which is `B6-F1`'s whole failure, closed in the only place it can be closed.**
- **No second publisher (`B6-F15`'s lesson):** the mirror broadcasts nothing and emits no descriptor; `IPC_RAG_STORE_CHANGED` keeps its one emitter, and no channel constant, no `preload.ts` byte and no `src/shared/types.ts` widening appears.
- **The mirror is INERT at construction** (the `B-4` discipline, `READ` `main.ts:874-894`): no read, no walk, no write at boot, so `main.ts` may build it beside the two engine proxies.

## 5. What the mirror must not break

- **`B-4`'s reconnect-by-re-read (`ASM-B-4`).** The mirror can neither fight the re-read nor widen it: (i) the re-read's answer is captured **by** the projection (`reconcile()` = walk + project + answer), so the two cannot disagree; (ii) the mirror answered from a **bounded** walk (`RECONCILE_PAGE_SIZE`/`RECONCILE_MAX_PAGES`, `READ` `main.ts:311-312`) so a partial list may **never license a delete** — a delete happens only on a **per-document** fact (a `deleteDocument` the engine accepted, or a summary-gone after a FULL walk has completed), never on absence from a truncated page — the shape `F-4` measures as a lie; (iii) `B-4`'s watermark, hold and fail-closed settle are untouched: `engine-changes.ts` takes **zero byte**.
- **`INV-E`.** The mirror writes the store and nothing else. No `loadAppGraph`, no `mountOperator`, no `refresh(` — and it *structurally cannot*: `engine-mirror.ts` imports no renderer and holds no host. Graded as a source clause **with one isolating mutant per conjunct**, driven false first (`D-40`'s `m6` lesson: a counter set that reads `0/0/0` because the whole branch is dead is not a proof — so the clause must also red under a deleted conjunct).
- **The store's single-writer discipline — and why `src/main/rag-store.ts` takes ZERO byte.** The projection goes through `applyBatch` (`READ` `src/main/rag-store.ts:279`, the atomic, one-journal-entry, one-persist writer the UI path already uses). A second, unjournaled writer would be a new store contract invented by a mirror, which is a widening this unit refuses. **The cost is NAMED, not hidden (`B4A-L1-1`, LOW, owner L0/next unit):** a mirror write is a journaled store write, so a local `undo` can remove a projection while the engine still holds the document — the doc-nav's next engine descriptor restores it, and with the feed parked (§8) it does not. That is a consequence of the engine being authoritative, not of the mirror.
- **A local document is never a projection's subject.** A local document whose id collides with an engine id is **refused** (counted `refused`) rather than clobbered: the projection marks its own root, and the mirror only ever updates or removes a marked root. A missing projection is `unchanged`, never a write.
