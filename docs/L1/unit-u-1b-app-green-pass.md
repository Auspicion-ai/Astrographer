## 2. The rows, and why each can fail

- **`uf_panes_8` — `UF-PANES-8`'s claim is re-pinned (the checklist cell carries it).** The block already pressed `#zone-collapse-left` and clicked a collapsed tab; it now also reads, at four instants (expanded → collapsed → after the drag → re-expanded):
  `extentCollapsedAuto` (`trackComputed === 'auto'`), `extentExpandedIsTheSize` (a `px` value), `extentContentDerived` (`0 < collapsed width < expanded width`), `collapsedGridColumnReclaimed` (the grid's first column ≤ 1), `controlExpanded.ok`/`controlCollapsed.ok`, the three gutter terms, `noResizeAfterTheDrag`, `stripLiveOnceExpanded`, and `dragLeftTheAppAlone`.
  **Why it can fail:** the token is authored TWICE (`ASM-U1b-10`) and an inline custom property outranks the sheet — a projection that stops emitting `'auto'` (or a sheet whose `:has()` mirror is deleted) changes the computed value, which no source census can see.
  **The resize-strip arm's TEETH, named so the claim is not overstated (`G5` finding 2):** the discriminating terms are the affordance's computed `visibility: hidden`, its **still-measurable** box (so "hidden by contract" is distinguishable from "the box collapsed away"), and the lane's hit test — collapsed: **not** the gutter, re-expanded: **the gutter itself**. The REAL CDP drag on the lane is RECORDED beside those terms and never relied on: at this head a real boundary drag does not resize an EXPANDED zone either (`UF-DEFECT-5`/`LIVE-UF7`, a carried confirmed defect), so "the width did not move" cannot by itself discriminate a gated strip from a broken seam. The drag's own worth is the class of failure it DOES catch — a drag that opens shell chrome (it opened the settings modal when its press was placed under `#settings-toggle`, which is how the harness bug below was found) — and it prints the modal's class around the gesture for exactly that.
  **What the first reading taught, and the row now states:** the container is `position: fixed`, so an `auto` track holds **nothing** — the grid column resolves to `0px` while the fixed container shrink-to-fits the tab strip (`83px`). The graded pair is therefore "column reclaimed AND the painted box content-derived", never "box equals column" (an earlier form of the term demanded exactly that and could not pass); and on that `auto` arm the CONTROL shrink-to-fits its own glyph (`20px`), so its tracked size is graded as "≥ the 20 px floor and ≤ its strip's extent", not as equality with the zone's `83 px`.
- **`uf_layout_10` — the `excluded` print becomes a verdict.** `ufZoneControlVerdict` grades every zone's control at one instant (the four zones are in three states there: `left` expanded-and-occupied, the other three empty ⇒ derived-collapsed) and a per-zone `zoneTrackAgreement` (collapsed-occupied ⇒ `auto`, empty ⇒ `0px`, revealed-empty ⇒ the persisted size, expanded ⇒ the persisted size), read as the **resolved** value the inline write wins. **Why it can fail:** the last `G8` reading would red five of its terms; a mirror/projection disagreement reds the agreement; a lost floor or a drifted control reds a named problem.
- **limb `I` (node, `zone-collapse-target.test.ts`) — the source clause that keeps the fix from being deleted silently.** It reads `index.html` and asserts the floor on both axes, the four positional rules' tracked axis, the two side rules' 32 px foot inset, the four collapsed-gutter `visibility: hidden` hides (and that they are not `display: none`), and the four gated `auto` extent mirrors — with **five mutations driven** (floor deleted; a tracked axis replaced by the floor; a gutter hide deleted; the foot inset deleted; an `auto` mirror ungated), each of which must red. **Layer:** source clause only — it does **not** prove the floor reaches the app.
